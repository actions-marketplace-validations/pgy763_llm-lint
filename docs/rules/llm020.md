## LLM020 事务方法里等异步结果

| 项 | 值 |
| --- | --- |
| 级别 | warning |
| 框架 | 通用 |
| 自动修正 | 没有现成补丁，按下面的改法手工改 |
| 更多 | https://github.com/pgy763/llm-lint/blob/main/docs/rules.md#llm020 |
| 关掉它 | .llm-lint.yml 里写 `LLM020: off`，或命令行 `--disable LLM020` |

事务的边界是方法，不是那段异步代码。方法里 block 一下、睡一会儿，数据库连接就从方法开始一直攥到方法结束——等的是模型还是别的线程并不重要，池子一样会被占满。把等待挪到事务外面，或者让事务只包住真正写库的那几行。

只想在某一处放过它：在该行或上一行写 `// llm-lint:ignore LLM020`。

## 为什么会踩

**搜这些能找到这条：** `事务里 block`、`@Transactional 里 sleep`、`拿不到连接`、`Connection is not available`


```java
// 会报
@Transactional
public void refreshAll(String orderId) {
    Flux.just(orderId).map(String::trim).blockLast();
}
```

改法：把等待挪到事务外面——先 `block` 拿到结果，再开事务只写库；或者把方法拆成两个，
事务只包住真正写库的那几行。

判断范围：方法（或所在类）带 `@Transactional`，方法体里出现 `.block()` / `.blockFirst()` /
`.blockLast()`、Future 上的 `.get()`、`Thread.sleep(`。内嵌类里的方法不看；`Thread.sleep` 可能是
限流退避，所以级别是 warning 不是 error。
